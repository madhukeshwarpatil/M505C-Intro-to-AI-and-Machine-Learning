1. Introduction and Problem Statement¶

The prices of used cars in the pre-owned cars market need to be quoted by used-car marketplaces and used-car dealers. Most of the used-car dealers resort to manual appraisal, which is time-consuming, inconsistent and not scalable. In this project, a supervised machine learning (ML) framework has been designed to predict the expected price at which a used car can be sold in India based on characteristics of the car when it is appraised for valuation. Formulation - The problem is modeled as a supervised regression problem where the target variable is the sale_price of a used car in India, which is a continuous value. The input features of the model are a set of variables that describe the vehicle being appraised (e.g., make, model, year, mileage, type of fuel, type of transmission, type of ownership) and the listing context (e.g., city where the listing was created, whether a warranty was attached to the listing). Note that variables generated after the vehicle listing (e.g., views on the listing, reservations on the listing, bookings on the listing) are not to be included in the model (Section 4). The goal of the model is to capture the association between the input features and the target variable, not the causation.

2. Data Collection¶

The dataset Used Car Price Prediction (India) contains information of 7,400 used cars listed online, which contains 29 features. It also contains the price of each car in sale_price in INR. The content of the dataset includes information of the cars like make, model, year of model, number of previous owners and usage (in km) etc. The dataset also includes information of the listing of the cars like views, quotes, and bookings etc on different online platforms. The dataset is publicly available on Kaggle at https://www.kaggle.com/datasets/vrajesh0sharma7/used-car-price-prediction and was downloaded manually and saved as a CSV file named “used_car_price_prediction.csv” (relative path to file). It is to be used for education purposes and no explicit licence is stated for its use. It is of sufficient size, contains a mix of numeric and categorical values, contains real quality and leakage issues, it wasn’t used in lectures for the module and it’s a laptop friendly size.

7. Models, Pipelines and Preprocessing Strategy Comparison¶

Models (meaningfully different):

  • Ridge regression (i.e. linear L2 regularized model): We can easily obtain signed coefficients from this model which are also meaningful. This model also assumes roughly linear effects for all variables. However, the variables are scale-sensitive.
  • Random forest (an ensemble of decorrelated trees) - captures non-linear and interaction effects; scale-invariant but less interpretable than Ridge regression and can overfit if left unchanged and fit on full training set.

Why pipelines: Pipeline + ColumnTransformer in the preprocessing chain re-fit all preprocessing steps on each fold of the CV used for training (and hence no leakage) while still allowing to tune the whole chain of preprocessing steps and to replicate easily.

Strategies (same 5-fold CV on training data for both models — fair comparison):

  • A: This strategy uses median imputation for missing values in numerical features most frequently and applies one-hot-encoding to features of type categorical.
  • B: A + StandardScaler (on numerics) - showing the required effect of scaling.
In [9]:
def preprocessor(scale):
    num_steps = [("imp", SimpleImputer(strategy="median"))]
    if scale:
        num_steps.append(("sc", StandardScaler()))
    return ColumnTransformer([
        ("num", Pipeline(num_steps), num_feats),
        ("cat", Pipeline([("imp", SimpleImputer(strategy="most_frequent")),
                          ("ohe", OneHotEncoder(handle_unknown="ignore"))]), cat_feats)])

models = {"Ridge": Ridge(),
          "RandomForest": RandomForestRegressor(random_state=RANDOM_STATE, n_jobs=-1)}
rows = []
for strat, scale in [("A: impute+OHE", False), ("B: A + scaling", True)]:
    for name, mdl in models.items():
        pipe = Pipeline([("pre", preprocessor(scale)), ("model", mdl)])
        cv = -cross_val_score(pipe, X_train, y_train, cv=5,
                              scoring="neg_mean_absolute_error", n_jobs=-1)
        rows.append({"strategy": strat, "model": name,
                     "CV MAE": cv.mean().round(0), "std": cv.std().round(0)})
base = pd.DataFrame(rows)

Decision: Go with Strategy B for Ridge and with Strategy A for forest. The forest is already doing better than Ridge by approximately ₹13k MAE, and matching the non-linear EDA results.

8. Hyperparameter Tuning (both models, 5-fold CV)¶

  • Ridge alpha: You increase the L2 strength. It shrinks the coefficients more with higher values of alpha (more bias, less variance).
  • Forest: The number of trees increases with reduction in variance at increased computational cost. The maximum depth of a tree can be limited by hyperparameter max_depth to prevent overfitting when set too low. Min_samples_split regulates tree splits by requiring a minimum number of cases for split at each node.

GridSearchCV evaluates all the values between all the hyperparameters using 5-fold CV on the training set only and uses the MAE score as the evaluation metric.

9. Final Model Selection and Test Evaluation¶

Selection: The tuned forest performs CV MAE of about ₹50.1k compared to tuned Ridge’s ₹62.6k. Selection cost here is lower interpretability. We report performance of both models on the hold-out test set once and report results in most business-readable form, i.e. average INR error (MAE).

Metrics: MAE is the average value of error in INR for each sample. MSE/RMSE is the square of large errors and hence large errors are penalized more. R² is the variance in y that our model explains vs simply predicting the mean of y.

In [13]:
def evaluate(m, X_, y_):
    p = m.predict(X_)
    return {"MAE": mean_absolute_error(y_, p), "MSE": mean_squared_error(y_, p),
            "RMSE": np.sqrt(mean_squared_error(y_, p)), "R2": r2_score(y_, p)}

The extra cost of Ridge for this problem is about ₹11,000. 200 deep trees are not human-traceable for a single car.

12. Business Implications, Strengths, Limitations and Deployment¶

Business meaning The average error is ≈ ₹46.7k on a median value of ≈ ₹3.8-lakh car which translates to ≈12% of the price for average-size car and ≈8.5% of the price for cars in ₹3–5-lakh band. It can be used as decision support for first-pass quotes, for check by human appraiser and for identifying mispriced used cars. However, for premium used cars errors can be in several lakh and hence one should show a range (e.g. ± MAE) instead of fixed number.

Strengths: leakage-audited features with an explicit prediction point for the error; one reproducible pipeline; two model families compared fairly; preprocessing effects are quantified; all CV-based-tuning is done on a single-use test set.

Limitations: We use listings from 2019–21 for 13 Indian cities. Prices for these used cars have drifted. Prices for used cars from other locations will not transfer. No condition, service-history, or accident data was available. The detail in the field variant was discarded. We have no way of estimating uncertainty in our point predictions. The target variable is severely skewed and thus was not log transformed (a simple additional experiment).

For deployment? Not yet. First validate performance on current listings, monitor drift, retrain from time to time. Send high-value cars (> ₹10 lakh) to human appraisers. Use this to provide a suggested price range within the listing workflow.

13. Conclusion¶

The main steps of the data-audit were (1) choosing a prediction point, (2) removing 4 impossible prices, 1 duplicate, as well as all target-derived and post-listing variables. For Ridge scaling was crucial while for the forest it was irrelevant. The deepest tuning worked best, and the resulting random forest had a test MAE of ≈ ₹46.7k, a test RMSE of ≈ ₹78.5k, and a test R² of ≈ 0.917. This corresponds well with the CV estimate. The most important features were age, body type, mileage, and brand/model identity. In terms of lessons learned, leakage discipline and data preprocessing are more important than model complexity. Future work includes log-target, gradient boosting, prediction intervals for listing prices, as well as a possibly more in-depth analysis of condition data and a larger set of fresh listings.
